# Daten の使用例：「基金の状況」

神Excel に Python で値を入れ、Excel で合計を再計算し、その結果を Python で読み出すまでを一周する例です。Converter・Bridge（proxy-to-kami／kami-to-proxy）・Python API をすべて使います。

## ファイル

| ファイル | 役割 |
|---|---|
| `kami.xlsx` | 神T：元の神Excel（値は空、合計列に数式） |
| `proxy.xlsx` | proxyT：神T から Converter で作った Proxy |
| `fill.py` | proxyT に値を埋め込み、proxyA を作る |
| `show.py` | proxyB から値を読み出して印刷する |

データ領域は W13:AC16 の4行×7列です。合計の2列（`積立基金*合計1～3` ＝ W＋X＋Y、`定額運用基金*合計1～2` ＝ AA＋AB）は数式で、残りの5列が定数です。

データセルの数値書式と日付体系を照合し、転記先の書式を保持します。その他のデータセル書式は比較しません（DECISION-13）。

## なぜ kami.xlsx は「神Excel」なのか

kami.xlsx は、人が印刷して読むことを前提に作られた帳票です。画面や紙の上ではきれいに見えますが、プログラムからは、どのセルが何の値なのかが読み取れません。

- **方眼紙のレイアウト**：A〜V 列は行見出しのレイアウトに使われ、大部分が幅の狭い列（1.625文字分）です。ただし、B 列は4.875文字分、P 列は1.75文字分、S 列は2.25文字分です。データは W 列から始まります。
- **見出しの文字がセルに分かれている**：「取崩し額」は D15・I15・N15・T15 の4セルに「取」「崩」「し」「額」と1文字ずつ置かれています。「歳計剰余金処分によるもの」も8つのセル（D16・G16・J16・M16・P16・Q16・S16・T16）に分かれています。
- **縦に並んだ見出しが複数の行にかかる**：「令和」「6」「年度」が B14・B15・B16 に縦に並び、14〜16行の3行すべてにかかります。
- **字間をそろえるための空白**：「積　　 　立　 　　基　　 　金」「2 減 債 基 金」のように、全角・半角の空白が入っています。
- **1つの見出しが2行に分かれている**：「その他特定目的基金」は「 そ の 他 特 定」（Y10）と「 目  的  基  金」（Y11）に分かれています。
- **見出しの階層が罫線と結合でしか表されていない**：「積立基金」が W〜Z の4列にかかることは、罫線を見ないと分かりません。「定額運用基金」は AA9:AC9 の結合で表されています。
- **番号がテキストボックスにある**：「その他特定目的基金」の「3」と「その他定額運用基金」の「2」は、セルではなく、セルの上に浮かんだテキストボックスに書かれています。

そのため、プログラムで「令和6年度の取崩し額のうち、財政調整基金の額」を読み書きするには、W15 という番地を決め打ちするしかありません。様式が少し変わるだけで、プログラムは黙って別のセルを読み書きします。

Converter で作った proxy.xlsx では、見出しが一つの Excel テーブルにまとめられ、行と列に名前が付いています。

    table["令和6年度*取崩し額", "積立基金*1財政調整基金"]

名前の `*` は見出しの階層の区切りです。`積立基金*その他特定目的基金3` の末尾の `3` は、テキストボックスの番号を Converter が見出しに取り込んだものです。

## 手順

### 1. 神T → proxyT（Converter）

`kami.xlsx` を Converter で開き、`proxy.xlsx` として出力・確定します。この例では作成済みです。

### 2. proxyT → proxyA（Python）

```powershell
python fill.py
```

`proxy-filled.xlsx`（proxyA）ができます。fill.py が書くのは定数の5列だけで、合計の2列には書きません（数式セルへの書込みは拒否されます）。この時点では、proxyA の合計列のキャッシュ値は 0 のままです。

### 3. proxyA ＋ 神T → 神A（proxy-to-kami）

```powershell
Daten.Bridge.exe proxy-to-kami --proxy-data proxy-filled.xlsx --kami-template kami.xlsx --output-kami kami-filled.xlsx
```

`kami-filled.xlsx`（神A）ができます。Bridge は定数だけを転記し、数式もキャッシュ値も変えません。そのため、神A の合計列はまだ 0 です。

### 4. 神A を再計算

`kami-filled.xlsx` を Excel で開き、**Ctrl＋Alt＋F9** で全数式を再計算して、**上書き保存**します。保存しないとキャッシュ値は更新されません。

### 5. 神A ＋ proxyT → proxyB（kami-to-proxy）

```powershell
Daten.Bridge.exe kami-to-proxy --kami-data kami-filled.xlsx --proxy-template proxy.xlsx --output-proxy proxy-result.xlsx
```

`proxy-result.xlsx`（proxyB）ができます。proxyT を土台に、神A の定数が入ります。合計列の数式は proxyT のものが残り、そのキャッシュ値は 4. で再計算した神A の値になります。

### 6. proxyB を読み出す（Python）

```powershell
python show.py
```

各行の7列の値を印刷し、合計列が再計算されているかを確かめます。正しく再計算されていれば、合計は次のとおりです。

| 行 | 積立基金*合計1～3 | 定額運用基金*合計1～2 |
|---|---|---|
| 令和5年度末現在高 | 36 | 29 |
| 令和6年度*歳出決算額 | 66 | 49 |
| 令和6年度*取崩し額 | 96 | 69 |
| 令和6年度*歳計剰余金処分によるもの | 126 | 89 |

4. を飛ばすと、合計は 0 のままで、show.py は「未再計算」と期待値を表示します。

## 注意

- 出力は毎回新しいファイルにします。同じ名前でもう一度実行するときは、出力を削除するか `--overwrite` を付けてください。入力と同じファイルへの出力は、`--overwrite` を付けても拒否されます。
- 合計列は Daten が計算するのではなく、Excel の再計算で埋まります。Bridge も Python API も再計算をしません。

数式の辞書風読取りは既存仕様で拒否されるため、show.pyは`extract`でキャッシュを読みます。値の一致は再計算実施の証明ではありません。`cache`は引き続き`unverified`です。`open_proxy`はoutputなしで定数を読めます。空セルはNoneであり、show.pyは合計対象の空セルを確認不能として扱います。
